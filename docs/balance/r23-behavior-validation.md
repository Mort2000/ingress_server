# r2.3 Bot 行为优化与验收

2026-09-05。本轮根据用户“继续完成 bot 代码优化，直到各个策略行为合理，符合预期”的授权，覆盖六个竞争 R2 策略。当前注册版本为 **r2.3**。本记录检验策略能否把合理的任务选择落实为实际动作和收益；不将机制调用次数或小样本胜负视为普遍强度证明。

前序结论见 [r2.2 机制修复与小型消融](r22-micro-validation.md)。r2.1/r2.2 原始报告、源码快照及运行目录保留；M6 策略、规则结算和回放格式未修改。

后续攻防专项复核见 [r2.4 攻防策略与收益对照](r24-combat-validation.md)：本报告的实际动作与回放验证仍成立，但 Adaptive 的阶段门槛限制了及时反攻，不能据此认定攻防能力充分或收益均衡。以下保留 r2.3 原始结果。

## 实现与机制验收

新增 `crates/arena-bots/tests/r23_mechanisms.rs`，22 项回归覆盖生产策略、共享分配边界和真实 Resolver。纯估值／分配场景用于隔离竞争关系，其余关键机制均有真实命令链验证。

| 范围 | 修复及预期行为 | 关键证据 |
|---|---|---|
| 共享建造 | 已有己方边作为建造进度；候选限额优先保留部分场；可直接闭场时按实际完成延迟估值 | 两条已有边可当轮闭场；末轮限额为 1 仍保留可完成的小场 |
| Key 获取 | 不反复索取已有敌方 Key；不为已经可执行的闭场补采无关 Key；远处不可及时使用的库存不能压制本地补采 | 本地 Hack → 下一轮 Move + Link，在两轮收官窗口内成场 |
| 分配 | 分配前过滤不可用 Hack；主、次计划之外的空闲人员通过同一预约板扩张；无三角形也适用；同轮 Link 预约还检查己方几何冲突 | 冷却请求让位于可执行 Capture；共线地图四名 Agent 均可扩张；相交对角线改选兼容边并真实结算成功 |
| 防守 | 按本次 Recharge 增加的**离散结算收入轮数**估值，扣除实际到达与 Supply 成本；考虑远程 Key、已结算威胁、生命周期和先后手 | 不拿整段场收入为 15 HP 补血记账；不能多保住一轮或敌方首击已致命时放弃；可救场时优先提交并实际存活 |
| 进攻 | 按实际到达顺序评估完整队伍前缀；限制伤害需求／人员份额；最终分配后复核期限和正净收益 | 不派赶不上拆场的远处人员；末轮两人可合拆 40 HP；关键队友转去建设后，无收益或超时的剩余队伍释放任务 |
| 运输 | 枚举可行交接组合，共用真实基础分配预览；只为提前成场交付所需 Key；按己方提交顺序先交接再行动 | 默认动作规则下 Transfer → 接收者 Move + Link 当轮成场；直连超出局长也可采用可完成的交接；无消费需求的 Supply 不转移 |
| 阻断 | 候选包括本轮 Move 后可执行的 Link；阻断收益仍扣除己方几何损失 | 真实对照中，原本合法的敌方连线被生产 Blocker 建出的边阻挡，Resolver 返回 `LinkIntersectsLink` |
| 混合策略 | 开局保留建造倾向；之后可同时竞争防守／进攻；收官保留可兑现收益的动作；角色标签来自实际分配 | 收官救场、多人拆场；重占清除旧威胁；角色预览与真实提交一致 |

进攻前后复核共用 `AttackArrival` / `strike_value`；物流预估和实际执行共用 `BuilderCore::preview_allocation`。这些共享入口避免“评分时一套任务、执行时另一套任务”。两轴代码审阅中的确定问题均已修复并补回归。

## 最终 Development 验证

最终批次为 `runs/balance/r23-verify-r3`。先前 `r23-verify-r1` / `r23-verify-r2` 为开发批次；后者用于发现 4 次己方同轮连线交叉。它们均保留，最终证据以修复后的 r3 批次为准。

- 两张已开放 Development 地图：`development-000`、`development-001`；默认规则；每对均换边。
- 六组竞争配对组成环：Greedy–Defender、Defender–Disruptor、Disruptor–Logistics、Logistics–Blocker、Blocker–Adaptive、Adaptive–Greedy。
- 六个策略分别对 Idle；共 **48 场、每场 500 轮**，每个竞争策略参与 12 场，其中 4 场对 Idle。
- 配置、地图和 game/bot seed 取自已归档 Development 输入，同一地图块跨配对复用；实际策略出生选择写入回放。跨配对样本有关联，不是独立胜率估计。
- 每轮另运行独立策略实例，逐项比较有序提交；每场完整 IARP 再验证逐轮状态和最终哈希。策略决策复现与规则回放分别执行。
- 明细保留任务、候选／不可用数量、位置、Key／Supply、命令、结果、计划、交接比较及场生命周期。

**48/48 场完成全部规则回放与独立策略提交复现。** 六个策略的 24 场对 Idle 全部成场并得分。六个竞争策略合计 180,000 Agent 轮、121,898 次任务授予，**获分但无提交为 0，原地 Move 为 0**；每次成功 Recharge 都恢复了 HP。

表中的攻击、补血、交接均取实际结算效果；场创建可包含同一结构被拆后的重建。无候选与预留冲突按分配记录区分，这些空闲不能直接记作实现故障。

主矩阵共记录 138 个命令 Drop：128 次捕获竞态、3 次连线端点归属竞态、7 次对手同轮连线造成的相交。逐项核对相交边的创建者后，**己方同轮相交为 0**。128 次无状态变化的提交均为捕获竞态；含成功移动但连线失败的提交也计入上述 Drop，并未被成功移动掩盖。

主矩阵中 Adaptive 的两个竞争对手均不进攻，因此其补血次数为 0。为补齐这个明确的覆盖缺口，另在相同两图、双腿中追加 **Adaptive–Disruptor 4 场**，归档于 `runs/balance/r23-adaptive-challenge-r1`，不混入上表。全部完成规则回放与独立策略复现。Adaptive 实际创建 174 次场，180 次有效攻击、36 次中和，44 次 Recharge 共恢复 640 HP；无空提交、原地 Move 或己方连线相交。

例如该追加批次 m0 leg0：R192–193，Agent 2 在 P73 连续完成有效补血；R491–493，Agent 10 使用 P93 Key 远程 Recharge，分别恢复 80→95、75→90、70→85 HP，说明收官阶段没有机械关闭防守。追加对局不是普遍强度证据，Adaptive 在这四场均负于 Disruptor。


## 运输对照与关键窗口

针对 Development 中实际出现的交接，额外固定一场 `builder-disruptor-r2--logistics-builder-r2-m1-leg1`，仅将 Logistics 的 `max_transfers_per_round` 设为 0，保留策略身份、其余参数、seed 和出生初始化，输出到 `runs/balance/r23-transfer-counterfactual-r3`。这是定向机制对照，不纳入上面的 48 场汇总。

## 结论边界

本轮关闭了已复现的任务分配、资源使用、收益归因和执行顺序缺陷。仍保留启发式限制：威胁依据已结算公开历史估计，无法预知对手下一轮的行动；计划限额、任务预留和几何约束仍会产生合理空闲；运输只接受可验证提前闭场的保守方案。这些限制与已修复的空提交、虚记补血收益及不可完成联攻有明确区别。

小型 Development 验证用于确认行为链，不能证明所有地图均最优、各策略强度均衡或任何策略普遍胜出。正式 B2/B3/B4 和 Holdout 的既有开放状态保持原记录；本轮没有使用 Holdout，也没有把该批次替代正式平衡验收。
