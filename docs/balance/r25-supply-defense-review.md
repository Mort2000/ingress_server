# r2.5：Supply 约束与防守策略抽查

2026-09-05。策略及上一轮评估已先提交为 `cfd2229`（`feat(bots): compose combat
and auxiliary actions`）。本次只做评估，未修改 Bot 策略、规则或 ADR，未分析 Transfer。
关注决策方向与明显失误，不做逐动作成本校准或局部寻优。

结论：**Supply 已会限制少数 Agent 的持续防守，但不是全队普遍缺资源；现有瓶颈
明显混有补采和移动规划缺口。** 两场回放都发现了可避免的补给机会损失，合法替代
命令也已在原始状态实际结算。应先补齐这两项基本行为，再判断 Supply 规则是否过紧。

## 1. Supply 是否构成瓶颈

扫描已有 r2.5 八图双腿的 Defender cap=2 与 Adaptive cap=2，共 32 场，无新比赛。
逐 Agent 核对每轮库存、实际 Hack 补给、实际 Recharge 消耗及期末余额，并复用
原分析器核对回放记录的收入与效果。每组包含 40,000 个实际可决策 Agent-round。

| 库存与使用，16 场合计 | Defender | Adaptive |
|---|---:|---:|
| 累计初始配给，含增援 | 2,240 | 2,240 |
| Hack 实际获得 Supply | 1,196 | 2,574 |
| Recharge 实际消耗 Supply | 774 | 918 |
| 期末 Supply | 2,662 | 3,896 |
| 出现轮前零库存的比赛 | 3/16 | 3/16 |
| 出现轮前零库存的 Agent | 4/112 | 4/112 |
| 零库存 Agent-round | 309（0.77%） | 209（0.52%） |

这不是“Supply 无影响”：资源由具体 Agent 持有，队友有库存不等于实际防守者可用。
最早的归零在 Defender m3/leg1 的 R217；抽样 Defender 的 Agent 6 在 R411–500
每轮轮前均为零。总体比例低，仍可能在一个关键锚点上形成真实约束。

但也不能把所有零库存轮都算成损失的防守机会：有时目标已消失，有时没有可达的
有价值锚点。对两场样本，从完整匹配的策略记忆进行只读敏感性检查：只把零库存
Agent 的观察库存补到一次 Recharge 所需的 1，其余观察、规划记忆和参数不变。

- Defender m3/leg0，R413：Agent 1、6 都为零；同时补到 1 后，分配会恢复两人
  对 P99 的充电。单独补其中一人则不会恢复，反映协同救场的资源门槛。
- Adaptive m6/leg0，R435、436：只把 Agent 6 从 0 补到 1，就会恢复 Agent 0、6
  对 P112 的双人充电；真实轨迹这两轮都没有充电，P112 在 R437 被拆。

这证明库存约束确实改变了防守选择。该检查不假定资源能凭空获得，也没有推进
改变后的整场比赛；不能把全部失场收入或最终胜负变化归因于 Supply。

## 2. 选样与可信度

在扫描后固定选择各组充电次数最多、且出现零库存的样本，属于**定向压力抽查**，
不代表平均对局，也不根据后续发现继续更换地图。

| 样本，均为 leg0 / ENL | 充电次数 | 最终己方 / 对手得分（10¹² score2） |
|---|---:|---:|
| `r25-combat-factorial-r2/def2-atk1-m3-leg0` | 92 | 22.590 / 133.661 |
| `r25-combat-adaptive-r2/adaptive-def2-m6-leg0` | 187 | 26.080 / 5.627 |

两场均重新验证全部 500 轮规则与状态 hash；按归档完整参数、bot/game seed、出生
选择和持续记忆重执行双方生产策略，所有有序提交一致。额外重建的请求级影子也
逐轮与生产策略的计划、分配、兼容任务及有序命令一致。候选原因来自这个匹配的
调用路径，不从最终动作倒推；没有给 Bot 注入敌方私有位置或资源。

全场扫描后再进入关键窗口：

- Defender：R12 成场、R17 遭首攻、R123 首次充电。R100 比分约 2.135/2.696，
  R300 为 8.966/56.847，R400 为 18.117/92.082。首次零库存在 R411，巨大落后

- Adaptive：R2 已反攻、R12 成场、R18 遭首攻、R30 首次充电。R200 比分约

  R435，此前已扭转领先，随后仍获胜；局部补给失误不使整场原始结果失效。

## 3. 明显失误一：缺资源后，反而失去顺手补采

Defender m3/leg0 的 Agent 6：

- R410 花掉最后 1 Supply，远程补 P99 后继续建设路线。
- R412 站在 P90，Supply=0，持有 15 枚 P99 Key；实际只发 `Link(P90,P99)`。
  P90 此时在操作范围内，Hack 冷却和 epoch 次数均可用，命令槽也充足。
- R413、414 仍在 P90、仍为零，既没有任务，也没有 Hack。P99 则从 R413 的
  25 HP 降至 5，R414 被拆，连带移除五个场。

已做合法单轮对照：从完全一致的 R412 状态，把同一 Agent 的流改成
`Link(P90,P99) → Hack(P90)`。真实 Resolver 确认原有命令效果和本轮双方收入
全部不变，新增 Hack 成功，流结束 Supply 从原来的 0 变成 1。
这不是要求寻找最优策略，只是原任务结束后漏掉了可用的辅助补采。

两场还分别有 36、11 个 Agent-round 满足“零库存、当前站位可 Hack、没有主任务”。
这些是原轨迹的重复机会快照，不能相加成可额外获得的 Supply：实际补采会改变
后续冷却及 epoch 限额。

调用路径说明：[build.rs](../../crates/arena-bots/src/r2/build.rs) 的
`allocate_and_execute` 对无任务 Agent 直接跳过，仅在授予 Combat 时调用
`compound::add_hack`。与此同时，[value.rs](../../crates/arena-bots/src/r2/value.rs)
会在 Supply 不足时过滤充电。这造成缺口：**缺补给 → 无充电任务 → 无附带 Hack**；
纯 Link 和空闲状态也没有独立的低库存补采兜底。

## 4. 明显失误二：远程充电者不主动向补给点移动

Adaptive m6/leg0 的 Agent 6：

- R415–434 一直停在 `(439961,379774)`，期间发出 19 次充电、没有 Move，
  Supply 从 19 用到 0。它持有 P112 Key，充电不要求留在原地。
- R430，Supply=5，只收到一个 Recharge(P112) 候选，实际也只充电。
  最近的 P99 位于 `(426707,384905)`，约 142 米，处于一轮 200 米移动预算内；
  当时并没有其他建设动作需要保留这次移动机会。
- 已从原 R430 状态实际结算 `Recharge(P112) → Move(P99) → Hack(P99)`：
  所有原有命令效果与当轮收入不变，新增 Move/Hack 成功；Supply 原轨迹为
  5→4，替代流为 5→5。并未假定 Hack 会随机产出未来所需的某枚 Key。
- R435 耗尽后，P112 的维护停止；同队 Agent 0 虽还有 17 Supply 和 P112 Key，
  当前单次充电估值没有产生候选。补给不足与单轮协同判断叠加，最终整个锚点退出
  防守。将 Agent 6 的观察库存恢复至 1，确实会重新产生双人救场分配。

所以 r2.5 **具备边充电边移动/建设/Hack 的执行能力，却没有主动安排补给路线的
规划能力**。`compound::add_hack` 仅检查已选路线的起点和终点；没有现成建设
移动任务时，不会为远程维护者寻找补采位置。这是策略能力缺口，不是细微的局部
最优问题。单轮合法对照没有模拟后续对手适应，不据此声称足以避免 R437 失场。

## 5. 建议与边界

下一步优先补齐合理的基本策略，不调整 Supply 规则，也不细调成本系数：

1. 低库存补采独立于 Combat 授予；兼容的 Link、移动和空闲状态都可触发。
2. 远程充电且没有冲突路线时，允许主动靠近可用补采点，避免站在空地持续耗尽。
3. 关注补给接替和维护连续性；不要只在库存归零后才发现原防守组合已经不可执行。

验证只需覆盖上述真实反例与少量同版方向对照，不要求每轮最优。本次没有实现
这些修复，没有运行“无限 Supply”的整局反事实，也没有评估 Transfer。
