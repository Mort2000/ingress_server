# r2.6：防守补给策略修复与验证

2026-09-05。承接 [r2.5 Supply 抽查](r25-supply-defense-review.md)。本轮只修复
明确的补采/路线缺口，比较方向性效果；不调规则、充电估值、Transfer 或 ADR。

## 冻结方案（运行前）

- 低库存补采不再依赖 Combat 分配；兼容已有 Link、移动与无任务状态。
- 没有已有路线的持钥远程充电者，以及空闲者，可向最近的当前可 Hack Portal
  移动；首版允许多轮移动，回放后收紧为一轮可达操作范围且能发 Hack（见下）。
- 原有任务、命令顺序与路线优先；不为补给移动近身无钥防守者或攻击者。
  遵守命令数、移动预算、Hack 冷却与 epoch 限额，不假设未来随机 Key。
- 参数 `supplyreserve=5` 表示库存不高于五次充电成本时触发；这是简单预警储备，
  不是寻优结果。`0` 关闭，旧参数缺省为 `0`。仅 Defender/Adaptive 默认启用，
  Logistics 与其他策略默认不变。

同一版本内固定对手 BuilderDisruptor（补给修复关闭），分别比较 Defender cap=2
和 Adaptive cap=2 的 `reserve0` / `reserve5`。沿用 Development 来源
`runs/balance/b2-readiness-rr-r3` 的 m0–m7、双腿，共 64 场（32 配对），默认规则，
不开放 Holdout，不搜索阈值。关闭组须与既有 r2.5 对应 32 场完整回放逐字节一致。

完整逐场核对规则、状态 hash、生产策略与独立影子有序提交，以及 Supply 收支。
微观样本提前固定为 Defender m3/leg0 和 Adaptive m6/leg0 的修复组，不根据胜负换样；
先扫描全场，再检查原故障附近的真实新轨迹，不能把旧轮号当作新局面。

观察指标：零库存与无提交轮、Hack 补给、实际充电/恢复量、边充电边移动/Hack，
最后才比较整局得分和胜负。无主任务但执行补给不能记成空闲。库存变好不自动证明
收益变好，更不把新的比分差归因于单一锚点获救。

## 结果

**两项基本行为已兑现；Supply 中断减少，但没有出现显著、普遍的整局收益提升。**
以下只汇总收紧路线后的 `r26-supply-*-r2`，每列每臂 16 场、40,000 Agent-round。
全部 64 场规则/策略提交核对通过；关闭组 32 场与 r2.5 完整 IARP 逐字节一致。

| 指标，关闭 → 开启修复 | Defender cap=2 | Adaptive cap=2 |
|---|---:|---:|
| 零 Supply Agent-round | 309 → 18 | 209 → 100 |
| 其中无提交的 Agent-round | 135 → 2 | 129 → 63 |
| 发生零库存的比赛 | 3 → 2 | 3 → 3 |
| Hack 获得 Supply | 1,196 → 1,272 | 2,574 → 2,610 |
| 成功充电次数 / 消耗 Supply | 774 → 832 | 918 → 900 |
| 实际恢复 HP | 11,495 → 12,350 | 13,640 → 13,370 |
| 同流成功 Recharge＋Hack | 265 → 315 | 263 → 275 |
| 同流成功 Recharge＋Move | 370 → 425 | 455 → 472 |
| 合并得分份额 | 6.009% → 6.082% | 62.119% → 62.097% |
| 胜场 | 0/16 → 0/16 | 13/16 → 13/16 |

Defender 配对分差改善 4 腿、变差 1 腿、不变 11 腿；地图双腿均值改善 3/8。
平均分差改善约 `0.598×10¹² score2`，相对原有巨大落后很小。Adaptive 改善
1 腿、变差 2 腿、不变 13 腿；地图均值改善 1/8，平均分差变化约
`−0.028×10¹² score2`。两组配对分差变化中位数都是 0。

这是方向性描述，不进行显著性检验。不能用更多充电或更少零库存替代收益判断：
Adaptive 甚至总充电略少，因为修复同时改变移动、Hack 得到的 Key 和后续任务。
本轮测量的是整个补给策略修复包，不是“纯 Supply 数量”的独立因果效应。

### 固定样本一：Defender m3/leg0

规则、双方生产策略及请求级影子全部 500 轮匹配。与关闭组首次有序命令差异在
R411，此前输入和动作相同。全场扫描：R12 首次成场、R17 遭攻击、R123 首次充电；
R100/200/300/400 己方/对手累计分数约为 2.135/2.696、5.569/24.459、
8.966/56.847、18.117/92.082（单位均为 `10¹² score2`）。补给变化前已明显落后。

- R400 不再启动首版的远距离补给绕路；R401 留在 P99 完成充电＋Hack，建设路线未变。
- Agent 6 在 R411 轮前 Supply=0，沿原路线到 P90 后执行
  `Move → Link(P90,P55) → Hack(P90)`，实际获得 1 Supply。R412 照常连
  P90–P99；R414 无主任务时仍可 Hack，库存增至 2。原版直到终局都维持零库存。
- 但 R413 Agent 1 在另一条建设路线上耗尽，Agent 6 虽有 1 Supply，却没有
  单人充电候选。此时 P99 为 25 HP、承载五个场；只把 Agent 1 的观察库存补到 1，
  请求影子就恢复两人充电分配。实际 P99 仍于 R414 失守。
- 最终己方/对手得分从 22.590/133.661 变为 23.723/132.725；仍明显落败。

这证明独立补采修复了 Agent 6 的停摆，但没有解决**整个维护组合的资源连续性**。
库存敏感性检查不是合法资源来源，也未将其继续推进成整局反事实。

### 固定样本二：Adaptive m6/leg0

同样完成全部 500 轮规则、生产策略和请求影子核对；首次有序命令差异正是 R430。
此前全场轨迹与旧版相同：R2 已反攻、R12 成场、R30 首次充电；R200/300/400
己方/对手分数约 2.108/2.516、6.274/3.342、11.466/4.257，已通过混合角色转为领先。

- R430 Agent 6 持有 P112 Key、Supply=5，实际执行
  `Recharge(P112) → Move(P99) → Hack(P99)`，补采成功，库存仍为 5。
- R431 开始在 P99、P119 间轮采；R435、436 不再因库存归零而停充。
  P112 的同一生命周期从对照的 R437 延续到 R452，七个关联场随后才被拆。
- 但它并未获得无限维护能力：两处 Portal 在本 epoch 各采满 5 次后，附近没有
  当前一轮可达的可采点；R448 再次耗尽。R450 Agent 0 仍有 10 Supply 和
  P112 Key，却因单次充电不足以产生正的整数存活轮增量而没有防守候选。
  将 Agent 6 的观察库存恢复至 1，会恢复 Agent 0＋6 的联合充电分配；
  R450/451 实际无充电，P112 的 HP 从 45 降到 25、5，R452 被拆。
- 局部维持更久不等于整局更强：R470 己方累计分从对照 21.638 提升到 23.774；
  但终局反而从 26.080/5.627 变成 25.303/5.299，己方分差减少 0.449。
  本轮没有把后续路线/建造变化进一步拆成独立收益，不能把锚点多存活 15 轮直接
  兑换成最终净收益；两条轨迹的对手均重新决策，没有沿用旧动作。

### 判断与下一步

1. 保留独立补采和有明确当轮产出的远程补给移动，这是合理的能力补齐；不以本轮
   胜率不变为理由撤回，也不将其宣传为已显著增强整体防守。
2. Supply 对少数持续维护者仍是实质约束；全队有库存不能代替维护组合可持续。
   但在该固定 Development 样本中，它不是纯防守巨大劣势的主要解释。
3. 继续迭代时优先检查“能持续补给的维护站位、维护者接替、何时撤守转建造/反攻”
   这类策略方向。多轮补给若要恢复，应有明确目的和连续计划，避免每轮重新挑
   最近可采点而折返；暂不提高 Supply 产量、微调充电估值或分析 Transfer。
4. 兼顾反攻的 Adaptive 仍明显强于纯 Defender，但两者是不同策略身份；本轮只
   消融补给修复，没有重新隔离攻击开关，因此不能据此宣称规则层面的攻防不对称
   已被精确量化或已找到唯一根因。

这轮使用 `review-bot-replay`，因此额外查出了首版的补给折返并收紧路线，最终仍
保留不利样本和剩余约束；没有根据结果更换地图或增加单点策略 ADR。

## 首版回放纠偏（最终批次运行前）

`r26-supply-*-r1` 保留原产物。Defender m3/leg0 的 Agent 6 在 R400 向较远的
可采点走出一步，R401 又因 epoch 重置返回 P99，R402–403 再离开，却在 R404
被建设任务重新调走。R408 提前耗尽，比对照 R411 更早。这是明显的未完成补给
绕路，而不是需要精细评分才能发现的问题。

首版不是“所有数值都更差”：Defender/Adaptive 零库存 Agent-round 分别降到
12/47，平均配对分差变化分别为 `+0.626/+0.860×10¹² score2`，均未改变胜场。
其整体数值甚至优于收紧版，但已确认的局部折返仍值得修正。收紧是保守的行为修复，
不是证明短路线全局优于长路线；带连续计划的多轮补给仍是后续可考虑的方向。

因此只收紧主动补给路线：一轮移动后必须能 Hack，且同时有 Move/Hack 命令槽。
没有这样的点就保留站位，不先走出无产出的补给路程；本地和已选建设路线的顺手
补采继续生效。局限是不会专门跨多轮寻找远处补给点。储备仍为五次充电成本，
不修改样本、规则或估值。最终在 `r26-supply-*-r2` 重跑同样 64 场，完整保留首版
构建与回放，不能混用两版 trace。
