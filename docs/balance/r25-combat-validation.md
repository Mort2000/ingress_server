# r2.5：组合动作后的攻防收益评估

2026-09-05。继续 [r2.4 攻防评估](r24-combat-validation.md)，优先修复用户指出的
“Recharge 不应排斥 Move / Hack / Link”能力缺口。只改 Bot，不改规则；Transfer
收益仍暂缓，未使用 Holdout，也不新增单点策略 ADR。

结论：组合能力已在实际结算中兑现，**纯建设＋防守仍被进攻严重压制，但及时反攻中
的防守已经出现正增量**。八图同版对照中，Adaptive cap 0→2 的平均分差改善
5.228×10¹² score2，12/16 腿、7/8 地图为正；不能再把纯 Defender 的劣势概括成
“防守普遍没有收益”。下一步检查资源约束和明显策略失误，不先修改规则。

## 本轮改变了什么

Attack、Recharge、Capture 共用每轮一个主动作槽；Move、Hack、Link 属于辅助动作。
攻击也能搭配辅助动作，防守的区别在于持 Key 可远程充电，更容易继续建设路线。
r2.4 对照准确记录了当时 Bot 的表现，但其单任务执行方式没有发挥这项能力，因此
不能把“某 Agent 补血一轮”等同于“该 Agent 一整轮无法建设”。

r2.5 引入一个可记录、可关闭的 `CoreParams.combat_auxiliaries`（序列化为
`combataux=0/1`，默认 1）。旧参数串缺失此字段时解析为 0，不替历史档案开启新功能。

- 保留原主任务分配，在同一预约板上增配一个兼容任务；一个 Agent 可以同时完成
  Combat 和建设辅助工作，但仍最多一个主动作。不是把两个任意任务直接拼起来。
- 远程 Recharge 可与原建设路线、Link 合并；本地 Recharge / Attack 只接受不冲突
  的移动路线。不同目的地不能分别领取完整移动预算；攻击后也不为了兼做建设而
  离开目标操作范围。
- 显式保留命令顺序：可先 Recharge，再移动、Link，避免 Link 先用掉最后一枚
  远程 Key。本次 Link 的可行性仍依赖已有 Key，不假定随机 Hack 会产出所需资源。
- 在已访问的位置至多增加一次可用 Hack，优先在充电后补回 Supply；遵守冷却、
  epoch 上限和命令条数。预览不记账，实际发出命令才更新 Hack 记忆。
- 攻击/救场的最终人数复核包含兼容任务；同轮 Link 继续检查共享几何预约。
  一个队员真的去执行 Capture 时，不能把其兼容工作误算成另一项主动作。
- 协同充电人数还受当前缺失 HP 约束，不把预测中的敌人攻击当作已预约的回血空间。
  这是首批回放暴露后的修复，对组合开关的所有实验臂一致生效。
  该边界较保守，可能放弃依赖精确敌我交错的救场机会，不能视作防守收益的理论上限。

动作评价的数值权重、预测窗口、Supply 系数、主动作的保守机会成本均保持 r2.4 值。
本轮先隔离**动作复用的实际效果**，并未把防守成本直接改成零，也尚未完成多轮维护
或组合方案的边际成本校准。基础 M6、纯建设行为和 Transfer 规划不在本轮优化范围。

## 最小回归与实际结算

诊断先运行 `cargo test --release -p arena-bots --test r25_combat --offline`。
最小化后，旧实现分别只发出 Link、Move、Recharge，三个组合能力断言均失败。
修复后的回归进一步覆盖最后一枚 Key 的顺序、主动作/命令上限、攻击侧 Link+Hack、
冷却记账、不可共享的 Capture 及残缺攻击队伍释放。

真实 Resolver 场景中，同一 Agent 既持有危急锚点的远程 Key，又持有新场闭合所需
Key；敌方本轮继续攻击 20 HP 锚点。开关对照结果如下：

| 组合动作 | 本轮结果 | 己方当轮 score2 |
|---|---|---:|
| 关 | 旧场被拆；新场建成 | 16,000,000 |
| 开 | 同一命令流先补血再 Link；旧场剩 15 HP，新场同时建成 | 160,000,000 |

这是固定场景的实际收入差，不是把恢复 HP 直接换算成分数，也不是整局强度证明。

面对旧攻击行为，单独给防守开启组合：自身平均增加 5.232，对手减少 6.168，净分差

攻击优势主要仍来自拒止对手收入，而非等量增加自己的产出；cap=2 下攻击开关

cap=2 中 265 次同流 Hack、45 次同流 Link、370 次同流移动；这些集合可重叠，
不能相加当成不同的行动轮。更多实际充电和更高己方得分都不足以替代净收益对照。

### 及时反攻中的防守增量

32 场全部通过复现和收入审计。以下仍为每场平均 `10^12 score2`。

| Adaptive 防守 cap | 胜场 | 自身得分 | 对手得分 | 汇总得分份额 |
|---|---:|---:|---:|---:|
| 0 | 8/16 | 7.725 | 7.744 | 49.94% |
| 2 | 13/16 | 13.350 | 8.141 | 62.12% |

同版开启防守，自身平均增加 **5.626**、对手增加 **0.397**，净分差改善 **5.228**；
中位数 +2.465，12/16 腿、7/8 地图为正。逐腿范围 -10.469 至 +30.922，仍有较大
波动，平均数不能代替分布。cap=2 实际充电 918 次、恢复 13640 HP；其中 263 次
同流 Hack、68 次同流 Link、455 次同流移动，同时仍执行了 3285 次攻击。

这比 r2.4 同版防守消融近零的平均增量更有希望，但**跨版本差不能全归因于组合动作**：
双方都升级了辅助行为，本轮也修复了协同充电人数的估算。真正支持“当前混合策略的
防守有收益”的证据，是 r2.5 内部固定对手、其余参数相同的 cap 开关对照。

因此当前建议是保留 Adaptive 的按需防守能力并继续优化，不能据此宣布 cap=2
全局最优，也不能将纯 Defender 的攻击开关增量 142.901 与这里的 5.228 直接比成
规则强度常数：两组策略、对手状态和计分基线不同。所有地图都是反复使用的
Development 输入，尚不支持总体统计显著性或正式平衡验收结论。

## 如何解释成本与下一步

规则存在明确的方向性不对称，但不能把它直接换算成同等幅度的净分数优势：

| 维度 | Attack | Recharge |
|---|---|---|
| 主动作 | 占 1 槽 | 占 1 槽；与 Attack / Capture 互斥 |
| 直接资源 | 不消耗 Supply | 消耗 1 Supply；持有远程 Key 不消耗它 |
| HP 作用 | 对范围内每个敌方 Portal 造成 20 | 单目标至多恢复 15，受满血截断 |
| 位置约束 | 必须进入攻击范围 | 本地可用；持 Key 可继续独立建设路线 |
| 辅助动作 | 也能 Hack / Link / Move，受范围与路线限制 | 可复用建设路线，合适位置可 Hack 回补 Supply |
| 场收益 | 拆锚点可能同时终止多个场的后续收入 | 保场只赚到实际延长的结算轮数，失守仍需重建 |

单目标持续施压且不截断时，补平 20 HP 至少需要平均 `20/15 = 4/3` 次 Recharge，
这解释了单人守单人攻的血量劣势；多人交错、先手、最后一轮结算和多目标攻击使
实际结果更复杂。Hack 的冷却/epoch 限额意味着一次组合流净 Supply 不变，不代表
长期维护没有资源成本。反过来，也不能把充电的 Agent-round 全额当成损失的建设轮。

按用户确认，现阶段关注**不同决策方向是否有明显且较稳定的收益差异**。
策略设计合理、能执行其方向即可；不以逐动作量化估值、成本系数校准或局部最优为目标。

1. 检查 Supply 是否实际限制防守：区分库存不足、补采负担与有资源却不防守，
   不仅依据理论上的充电耗费判断瓶颈。
2. 抽查一两场 Development 回放，寻找明显的计划失效、重复赶路、漏防和错误
   人员分配；先排除这些行为偏差，不为每轮寻找最优替代。
3. 后续用合理的建设、进攻、防守与混合策略比较整局收益及跨地图方向，
   差异不明确时保留“不足以区分”的结论，不靠细调系数制造优势。

这些是待验证的策略工作，不是 ADR，也不构成提前调整攻防规则的建议。

## 固定回放窗口

固定选 m0 leg0 的 Defender 和 Adaptive；先看全场成场、首攻、阶段比分和任务，
再跟踪组合 Link / Hack 的收益及后续失场，不为了挑成功例子更换地图。

Defender 的双方组合开启场（`daux1-aaux1-m0-leg0`，同后续 `def2-atk1-m0-leg0`）：
R100 得分约 1.226 对 3.687，R250 为 2.670 对 18.724，最终为 5.458 对 115.235。
组合能力没有避免持续落后的全局局面。

- R147，Agent 0 沿 P1 的 Link 路线移动。
- R148，主任务仍为 Link，同时获 Recharge(P102)；先恢复 60→75，再沿原路线移动。
- R149，Supply=25，完整流是 `Recharge(P102) → Move → Link(P1,P102) → Hack(P1)`。
  充电 75→90；Link 闭合 `[1,58,102]`；Hack 获 2 Key、1 Supply，流结束 Supply 仍为 25。
  因此这轮充电既未丢掉建设动作，也没有造成净 Supply 库存下降。
- 新场结算 R149–152，R153 与 P102 的另外两个场一起被拆。其实际四轮收入为
  100,922,390,508 score2，但不能把这些收入全部归给 Recharge：Link、原有结构和
  对手后续行为共同影响结果。

该窗口支持“充电可以复用建设行动并就地补采”，不支持“所有充电零成本”或“已经
证明整个防守方案更强”。精确候选评分未逐项导出，不从最终动作倒推评分差值。

Adaptive 的固定场 `adaptive-def2-m0-leg0` 也已核对 r1/r2 回放逐字节一致。
己方 R2 已攻击、R12 首次成场；对手 R16 首攻、R28 首次成场。R100 得分约
1.462 对 0.478，R250 为 4.760 对 1.909，最终 10.430 对 10.327。

- R253，Agent 2 返回 P85，同流移动、充电 80→95、Hack；Supply 从 38 扣减再
  回补至 38。但 R254/255 仍需继续充电，且本轮无 Hack，Supply 分别降至 37/36。
  R256 该锚点的三个场仍被拆，补采并非永久免费维护。
- R459，Agent 8 沿 P107 建设路线移动，同时远程补 P93：80→95。
- R460，同流 `Recharge(P93) → Move → Link(P107,P93) → Hack(P107)`，补血
  75→90、Supply 仍为 26；这次 Link **没有直接成场**。
- R461 同 Agent 再 Link，才闭合 `[93,107,119]`；R464 被拆，实际结算三轮，
  共 39,693,779,982 score2。不能把 R460 的所有组合流都统计成“补血同时成场”。

该固定腿虽然 cap=2 小胜，cap=0 的分差却更高：约 +1.524 对 +0.102；开启防守
反而使分差少约 1.422。局部组合成功、最终获胜与防守的正增量是三个不同判断。
