## Environment constraints (read first)

- **Offline-first since M8**: the dependency closure is COMMITTED under `vendor/`
  and `.cargo/config.toml` redirects crates.io to it — builds need no network.
  `rust-toolchain.toml` pins 1.98.0 (+rustfmt); the rustup proxies honor the pin.
  If the pinned toolchain is missing, EVERY cargo command in the repository fails
  until `rustup toolchain install 1.98.0 --profile minimal --component rustfmt`
  runs (the one out-of-band network step; see docs/build-provenance.md).
- **Network works through a configured cargo mirror** (crates.io is reachable via
  cargo itself; direct curl to the default CDN times out — probe with cargo, not curl).
- **Dependency policy (ADR-0013, amended for M7)**: official `blake3` only until
  M7; M7 adds `planus` (pure-Rust FlatBuffers-compatible compiler + runtime — the
  wire format is FlatBuffers; planus generates planus-runtime code, so the
  official flatbuffers crate is NOT used; generated code is committed so builds
  do not require planus). Everything else stays std-only.
  Never add other dependencies without recording it in an ADR and here.
  (M9 note: `arena-runner` gained the `arena-server` workspace PATH dep —
  in-tree member, no registry source, lockfile unchanged; recorded in D79.)
- Toolchain: rustc/cargo 1.98.0 (pinned, at /usr/bin proxies), 12 cores, 7.7 GB RAM.
- Sandbox facts (M8): landlock ABI 7 live; `/sys/fs/cgroup` NOT delegated
  (EACCES → recorded degradation); `PR_SET_NO_NEW_PRIVS` = 38 here.

## Conventions for milestone agents

- Never `git commit` (orchestrator commits per milestone); keep `Cargo.lock` current when deps change.
- English comments; identifiers use CONTEXT.md terminology (Faction/Agent/Portal/Link/Field/Score).
- `arena-core`/`arena-replay`/`arena-bots`/`arena-runner` stay `#![forbid(unsafe_code)]`.
- M7 unsafe policy: `arena-protocol` is `deny(unsafe_code)` with ONE scoped `allow` over the
  three planus-generated modules (planus's table writers contain audited `unsafe`); `arena-server`
  and `arena-client-sdk` are the same shape with exactly one sanctioned module each — `shm.rs`
  (POSIX syscalls via `extern "C"`, no libc crate; since the M9.1 review round the arena-server
  module additionally wraps `getsockopt(SO_PEERCRED)` for accepted-peer identity — still the one
  module, same shape), documented invariants, safe wrappers
  (P4-CAPABILITY). A stray `unsafe` anywhere else still fails the build.
- M8 unsafe policy: `tools/sandbox-runner` is `deny(unsafe_code)` with exactly ONE scoped
  `#[allow(unsafe_code)] mod sys` (setrlimit/prctl/landlock/kill via `extern "C"`, no libc
  crate; the `pre_exec` assembly lives there too — direct syscalls only, async-signal-safe).
  Every other tools crate and every participant crate is `#![forbid(unsafe_code)]`
  (audit-enforced, R1).
- Authoritative math: integers only, i32 coords promoted to i64 before subtraction,
  checked arithmetic, `Area2(u64)`, `Score2(u128)`; no floats in authoritative code.
- Handoff state: `cargo fmt --check` clean, `cargo test` green.

## Frozen design decisions (must not silently change)

- D1: `blake3("")` hex starts `af1349b9f5f9a1a6` (verified against pinned blake3 1.8.7; the `…a1a7` form is wrong).
- D2: canonical encodings use fixed-width unsigned little-endian integers, concatenated without padding.
- D3: `HACK_KEY_YIELD DiscreteUniform{1,2,3}` = `1 + uniform(addr, 3)`; config stores min/max (1,3).
- D4: `CLUSTERED_PORTAL_RATIO` stored as permille u32 (default 700); clustered count = floor(count·permille/1000).
- D5: `PORTAL_CLUSTER_COUNT` is one config u32, default 6.
- D6: cluster spread = `4 × portal_min_distance`; per-axis gaussian-like = clamped Irwin–Hall of 3 uniforms.
- D7: generated portals start Neutral with hp 0.
- D8: `segments_intersect` is the pure CLOSED predicate; R-LINK-02 endpoint/touch exceptions are composed by link rules, not geometry.
- D9: promote i32→i64 before any subtraction/square/cross; checked ops with `expect("bounded by GameConfig::validate")`; no floats/wrapping/saturating.
- D10: config validation caps (dims ≤ 2^20 cm, distance params ≤ i32::MAX, portal_count 2..=10_000, min distance ≥ 1) guarantee runtime checked ops cannot overflow.
- D11: `uniform(_, 0)` panics (documented); `n == 1` naturally returns 0.
- D12: map generation is pre-match tooling on its own `"AMAP"` blake3 stream — never `RandomOracle`, never replayed.
- D13: spawn-set errors: per-entry submission order (unknown → duplicate → out-of-bounds), then missing ids sorted; no coordinate-coincidence checks.
- D14: `Command` enum currently carries only `Move`; later milestones add the rest. (Superseded in M2: Move/Attack/Capture/Recharge.)
- D15: `game_seed: u64` is match-setup input (Replay Header material from M5); RandomOracle is the only runtime randomness source.

M2 (Basic Combat) additions:

- D16: modules — `state.rs` (GameState + round trackers + mutations), `event.rs` (broadcast events), `resolve.rs` (intake, ordering, execution, per-command results), `observe.rs` (faction views), `harness.rs` (in-process loop, scripted strategies). DROP/outcome types live in `resolve.rs`.
- D17: roster — `GameState::new` derives agents ENL `AgentId(0..n-1)`, RES `AgentId(n..2n-1)`, `n = initial_agents_per_faction`; `initial_roster(cfg)` feeds `validate_initial_spawn_set`; the constructor rejects spawn sets not exactly covering each roster.
- D18: virtual receive — strategies state a bucket directly; the harness sets `received_at_ms = bucket * priority_bucket_ms`, per-faction `receive_seq` = collection order. Public pure `receive_bucket(at_ms, bucket_ms) -> u64` (floor div), boundary-tested. Default bucket 0 (ADR-0002).
- D19: merge — per bucket (ascending); each faction's queue sorted by `(received_at_ms, receive_seq)`; alternation starts at the round's start faction and restarts fresh in every bucket; one queue empty ⇒ drain the other in order.
- D20: start faction from parity only — odd round ⇒ ENL (RES notified first), even ⇒ RES. No separate signal-order input in M2.
- D21: locatability (core envelope analog) — wrong `round`, unknown agent, or faction ≠ agent's faction ⇒ recorded unlocatable, slot NOT frozen (R-RESOLVE-01 "envelope reject doesn't freeze"). All other transport concerns are M7.
- D22: round close — agents with no submission when input closes are frozen PASS (deadline analog). No COMMIT_ROUND in-process in M2.
- D23: zero-target ATTACK ⇒ DROP `AttackNoEnemyPortalsInRange` (state-identical to a no-op success; chosen for per-command observability). The major quota is consumed either way.
- D24: DROP taxonomy — one variant per distinct rule failure, no catch-all (see `DropReason` in `resolve.rs`).
- D25: attack ordering — enemy portals in closed range are damaged in ascending `PortalId`; per portal emit `PORTAL_ATTACKED` then `PORTAL_NEUTRALIZED` if hp reaches 0. `GameState::neutralize_portal` is the documented M4 link/field-cascade extension point (today: `owner=Neutral, hp=0` only).
- D26: integer clamps — hp floor via `checked_sub(damage).unwrap_or(0)` (game clamp, not an overflow escape); recharge sum in u64 then `min(portal_max_hp)`; `event_seq` is global, 0-based u64.
- D27: structural vs execution — structural = commands ≤ `max_commands_per_agent_round` AND majors ≤ 1 (count-only, world-blind). Unknown `PortalId` is execution-time `PortalNotFound`, never structural.
- D28: major-on-drop — `major_used` is set even when the major DROPs; intake caps majors at 1 per stream so double-spend is unreachable — the tracker fact is for spec compliance, later milestones, and tests.
- D29: placeholders — scores stay `Score2(0)`; no links/fields until M4; `Observation` still exposes scores (R-VIS-01).

M3 (Economy) additions:

- D30: `Command` grows `Hack { portal }` and `Transfer { target_agent, supply, keys: BTreeMap<PortalId, u32> }` (BTreeMap = canonical ascending order + free dedup); both auxiliary. The payload names no sender — the stream owner is the sender by construction (R-TRANSFER-01). `Command` drops `Copy` (keeps `Clone`).
- D31: hack RNG stable index = per-`(agent, portal)` LIFETIME count of successful hacks (0-based, never reset by epochs); address = frozen `RandomOracle::hack_address(round, agent, portal, ordinal)`, `RNG_VERSION` stays 1 — epoch-local ordinals would shift every draw after an `EPOCH_LENGTH` retune.
- D32: `GameState::epoch_index(round, epoch_length) = (round - 1) / epoch_length` (0-based; rounds are 1-based, floor div). Epoch reset is EAGER inside `advance_round`: on a boundary, every hack tracker resets `last_hack_round`/`hack_count_epoch` while `hack_ordinal` survives — "Round 100 hack must not block Round 101" is a plain state fact.
- D33: `Resolver` owns a by-value `RandomOracle` — `Resolver::with_seed(game_seed)` is the authoritative constructor; `Resolver::new()`/`Default` stay seed-0 for M2 fixtures. `MatchHarness::new(game_seed, cfg, map, spawns, enl, res)` takes the seed first; `GameState` never holds seed or oracle (D15).
- D34: HACK validation order is contractual: portal exists → closed `PORTAL_OPERATION_RANGE` from the current position (NO owner check) → cooldown → epoch limit. A passing hack always succeeds and draws exactly one sample (`min + uniform(addr, max-min+1)`); supply grants CLAMP at `MAX_SUPPLY` in u64 (a clamp is not a failure; keys never clamp; tracker still advances). Dropped hacks mutate nothing and draw nothing. Range failures reuse `OutOfOperationRange`; when cooldown AND epoch limit both fail, cooldown reports.
- D35: TRANSFER validation order is contractual: target exists → same faction → closed `TRANSFER_RANGE` from CURRENT positions → sender supply → sender key balance per portal ascending `PortalId` (zero-count entries inert, first shortfall reported) → receiver `supply + transfer <= MAX_SUPPLY` (u64 sum; `capacity` in the DROP reason is the receiver's REMAINING headroom). Any failure ⇒ DROP with zero mutation; sender key entries depleted to 0 are removed (canonical inventory for M5 hashing); self-transfer and zero-quantity transfers are legal no-ops that still pass target/faction/range checks.

M7 (External Runtime) additions:

- D60: protocol contracts — three committed `.fbs` schemas (`crates/arena-protocol/schemas/{protocol,public_snapshot,private_snapshot}.fbs`, one root each because planus takes one `root_type` per file) with generated Rust COMMITTED under `src/generated/` and rebuilt only by `scripts/regen-protocol.sh` (planus-cli 1.3.0 pinned; the script strips planus's unconditional `::serde::Serialize/Deserialize` derives and rustfmts; builds NEVER require planus). The eager "Verifier gate" is root-`*Ref`-to-owned conversion (planus validates lazily; `TryFrom<Ref> for Owned` walks every field of the matched union variant, vectors included). FlatBuffers file identifiers `IENV`/`IPUB`/`IPRV` are stamped at the buffer head and checked on decode — without them a short envelope vtable can decode as a snapshot of defaults, defeating the "wrong root / cross-partition" rejection the plan requires; planus writes `[identifier][root_offset]` and has no read-side identifier support, so the decoders slice the 4-byte tag off before `read_as_root`.
- D61: handshake — the CLIENT_HELLO version triple (protocol/public/private) must match all three server constants EXACTLY; both HELLOs are collected before either SERVER_HELLO is answered; any mismatch aborts BEFORE any SHM region exists or INITIAL_SPAWN_START is sent, as an unscored `SetupError` (never SPAWN_FORFEIT), and BOTH connections receive SERVER_HELLO status=1. First version-valid HELLO -> ENL, second -> RES (accept order).
- D62: framing — u32-BE payload-only prefix; LEGAL maximum 65,535 (ADR-0008's 65,536 is the exclusive ceiling: a 65,536 prefix already declares over-limit); the prefix is checked before it can influence any allocation (the reader only accumulates bytes that actually arrived); over-limit poisons the reader and the connection is closed WITHOUT draining — pre-start an unscored SetupError, post-INITIAL_SPAWN_START a CLIENT_FORFEIT for that side. In-limit undecodable buffers (flipped bytes, truncation, empty payload) are recoverable envelope rejects: nothing freezes, the connection lives on. `SubmissionResult` status codes: 0 accepted-first (slot frozen), 1 rejected-structural (frozen, ADR-0004), 2 ignored-duplicate, 3 unlocatable (wrong/future round, unknown agent, faction mismatch — nothing frozen), 4 late-drop. REVIEW FIX (M7.1): the config field is the EXCLUSIVE ceiling; `MatchInfo.max_frame_payload_bytes` publishes the ENFORCED legal maximum (derived from `arena_protocol::MAX_FRAME_PAYLOAD_BYTES`, documented in protocol.fbs) so a client sizing its largest frame to exactly the advertised value is legal; `serve_match` rejects configs whose ceiling disagrees with the compiled-in constant (infrastructure defect, before anything is bound).
- D63: SHM — three regions per match `/ingress-<match_id>-{public|enl|res}` (0600, O_EXCL with stale-replacement, unlinked on drop), layout `[metadata page 4096][buffer A][buffer B]`, capacities public 8 MiB / private 2 MiB per faction, oversize payload = infra abort never truncation. Publish = copy into INACTIVE buffer -> `seq.fetch_add(1, AcqRel)` (odd; the acquire half pins the later metadata stores behind it) -> flip `active`/`snapshot_version`/`current_round`/timing -> `seq.store(even, Release)`. Readers Acquire-load even, snapshot metadata + ACTIVE payload, decode in place, re-load Acquire and retry on inequality (<=64 retries); `snapshot_version >= last_seen` refuses stale lends; `magic/layout_version/region_kind/schema_version/capacity` are immutable and checked before any read. The server's `shm.rs` (publisher) and the SDK's (reader) carry byte-identical `MetadataBlock` twins pinned by compile-time offsets and a cross-crate test.
- D64: receive mapping — `received_at` is the `Instant` of the LAST payload byte of the complete frame (stamped in the reader thread); per-connection `receive_seq` is strictly increasing and never reset (one connection == one faction, so it IS the Faction Receive Sequence); the Resolver's `received_at_ms = (received_at - round_start).as_millis()` saturating at 0, so `receive_bucket = floor(elapsed/priority_bucket_ms)` exactly as the harness's D18 derivation. Frames completing at/after the CURRENT round's deadline are transport-dropped (journal `late_drop`, reply status 4, never forwarded, slot unfrozen); frames claiming an already-CLOSED round (claimed < current) are dropped the same way (the cross-deadline half-frame can complete several rounds late under load); claims of a FUTURE round stay envelope-unlocatable WrongRound (forwarded, nothing frozen). REVIEW FIX (M7.1): a frame whose claim equals the CURRENT round but which completed before that round's ROUND_START_SIGNAL was written (the pipelining exploit: SUBMIT_COMMAND_STREAM(round N+1) fired on observing ROUND_CLOSED(N), completing during settlement or the N+1 snapshot publish) claimed a FUTURE round at arrival — no honest client can submit for a round before its signal — so it is transport-level unlocatable (reply status 3, journaled, nothing frozen, NEVER forwarded: its claimed round equals the current round, so the resolver could not reject it itself; unlike the in-round future claim it therefore does not appear in the replay's unlocatable echo, matching the late-drop frames). This removes the guaranteed bucket-0 first-mover priority a pipelining client would otherwise buy every round.
- D65: server threading — one accept-loop thread (exactly two accepts; every further connection gets SERVER_HELLO status=2 then close), one reader thread per connection (frames, timestamps, eager decode -> one mpsc channel), and ONE driver thread owning the write halves, `GameState`, `Resolver::with_seed`, `ReplayWriter`, SHM publishers, journal, metrics; `recv_timeout` until the active deadline so a slow client never blocks settlement (reader threads keep draining; late frames drop per D64). M7 deviations from the architect plan (spec wins / noted):

- planus cannot be avoided for the generated code's `unsafe` table writers, so arena-protocol uses `deny(unsafe_code)` + a scoped `allow` on the three generated modules (hand-written code remains unsafe-free); arena-server/arena-client-sdk use the same deny+scoped-allow shape for their single sanctioned `shm.rs` each (a crate-level `forbid` cannot be lifted per-module).
- FlatBuffers file identifiers (IENV/IPUB/IPRV) added beyond the sketch: required for the "wrong root type rejected" and "cross-partition" checklist items — without them planus happily decodes one root's buffer as another with default fields.
- `RoundStartSignal`/`CmdEmpty` for Attack: the sketch's union table listed `Attack: CmdPortal, Recharge: CmdEmpty`, which is inverted (Attack carries no payload, Recharge takes a portal) — implemented per the rules.
- `SubmissionResult` carries two extra statuses (3 unlocatable, 4 late-drop) beyond the sketch's 0/1/2 so every transport verdict is observable by clients and tests.
- `MapView` (pre-match public snapshot) and the SDK run() bot factory `FnOnce(Faction, &GameConfig, &MapDefinition)` exist because M6 bots need the frozen map at construction (D54) and the faction only arrives at SERVER_HELLO; `submit()` returns a fire-and-forget `SubmissionAck::Sent` — the server's authoritative verdict arrives asynchronously as SUBMISSION_RESULT and is surfaced via `Session::last_submission_result`.
- Match-end teardown drops the write halves instead of shutdown(Both): with unread inbound data a SHUT_RDWR RSTs the socket and can destroy the final GAME_END frame (observed live); the no-drain close the spec demands is kept for over-limit termination.
- The timeout-rate metric counts only missed-deadline slots; slots frozen by a prompt COMMIT_ROUND are deliberate empty passes (`committed_passes`), otherwise a fully-prompt committing faction would score 1000 permille "timeouts".
- Client-side read loops drain buffered frames BEFORE blocking on the socket: the server pipelines ROUND_CLOSED + the next ROUND_START_SIGNAL in one write, and a blocking-first reader would stall the buffered frame until the next unrelated write, missing entire rounds (found live via per-round client timing; fixed in SDK `Connection` and the test `RawClient`).
- Conflict-win-rate metrics deferred to offline replay analysis (plan-sanctioned D70); spawn forfeits write no IARP (no `GameState` can exist without both spawn sets).
- `cargo test` default run includes everything (no M7 test is `#[ignore]`d): the full workspace suite takes ~2 min wall, dominated by the pre-existing M5/M6 gates (1000-match replay gate ~15 s, runner gate ~33 s) and the compile-fail harness (~14 s, two throwaway cargo builds against a shared target dir). `ARENA_SKIP_LIVE=1` skips the live-match file during tight iteration.
